## 복구 우선순위

1. Vercel Production/Preview와 GitHub Actions의 실제 Supabase 대상, `MIRROR_SUPABASE_*` 설정 여부를 인증된 계정으로 확인한다. 기본 DB와 별도 미러 DB의 크기/갱신 상태를 각각 측정한다.
2. 기본 DB 또는 실제 배치 대상 DB에 용량 가드 RPC와 미러 분리가 적용됐는지 확인한다. 423.8MB DB에 가드 없이 크롤을 재개하지 않는다. 방출 정책과 공간 확보 방안을 먼저 결정한다.
3. 180일/30일 갱신 backlog를 용량·처리량 한도에 맞춰 단계적으로 처리할 계획을 세운다. 배치 재개와 데이터 수정은 이 점검의 범위에 포함하지 않았다.
4. 원격보다 앞선 4커밋을 검토하고 배포 경로를 확인한다. 웹 lint 오류와 Node 26 테스트 환경 설정을 정리한다.
5. 알림·PostHog 정기 작업의 비활동 중지 원인을 확인하고, 필요한 작업만 재개한다.

로컬 Vercel CLI는 54.9.1이며 인증되지 않았다. 배포 설정 확인 전 최신 CLI로 업그레이드하는 편이 좋다.
